Aeroplan Anti-Bot: Doing vs. Should Do vs. Stop

What we already do to stay un-flagged, what to add, what to remove · code audit + 2026 defender research · login-velocity & scripted-input axes (IP scope excluded per request)

The reassuring headline: defender research says the #1 lever for not getting an account flagged is logging in as rarely as possible on a warm, consistent session — and that is exactly where our architecture is already strong (warm persistent profile + skip-login-when-still-authed + detect-and-bail). Our weak spots are all secondary: burst pacing of the rare re-logins, and machine-like keystrokes/timing at the login form.
The one counterintuitive trap (new finding): uniform random jitter is itself a detection signal. Defenders (Varonis "Jitter-Trap", FCaptcha keystroke biometrics) run distribution + autocorrelation tests, and a flat random.uniform() spread is a recognizable fingerprint. The fix isn't "add jitter" — it's log-normal / fat-tailed timing. This affects both the fixes we add and the uniform jitter we already use in the scraper.

✅ What we're already doing right

Login velocity — structurally strong

  • Warm persistent profile — cookies survive across runs, so most runs skip login entirely. The single biggest lever, and we have it. core/aeroplan_session.py:78,195-202
  • ensure_logged_in cheap-checks first and returns without logging in when the session is still alive. Combined with the warm profile, a fresh process often performs zero logins. core/aeroplan_session.py:249-282
  • Watch refreshes already pass --max-reauths 1. The highest-frequency automated path is already capped tight. core/watchlist.py:207
  • Resume-from-next-unscraped-window — never re-scrapes done windows, minimizing sessions per span. core/aeroplan_runner.py:50-89,271
  • Expired-on-final-window short-circuit — skips a pointless re-login when expiry hits the last window. core/aeroplan_runner.py:87-88,214-217
  • Scheduler interval floors — 60 min hard floor, ~75 min computed minimum for one Aeroplan route. Caps scheduled login frequency. core/scheduler.py:37-38,373-374
  • max_reauths cap + single-route design + max_windows=12 ceiling. Bounds worst-case login storms; one login amortized over one route's windows. runner.py:42,119 · cli.py:645

Behavioral / scripted input — strong on identity, good instincts

  • Real headed system Chrome (not bundled/headless) — authentic input events, fingerprint, TLS. Headless is refused by construction. The dominant realism factor. core/aeroplan_session.py:113-134,195-202
  • Detect-and-bail on Arkose — we NEVER submit a synthetic, behavior-empty challenge token. The single worst behavioral tell (empty mouse-array token) is one we structurally never emit. core/aeroplan_session.py:378-405,538-548
  • Anti-automation launch flags — navigator.webdriver stripped, automation infobar removed. core/aeroplan_session.py:200-201
  • Signal-driven (not fixed) waits around submit — dwell reflects real server latency, so it varies naturally. core/aeroplan_session.py:554-574
  • Per-window jitter already present on the scrape loop. Good instinct — but it's uniform; upgrade to log-normal (see "Should Do"). core/aeroplan_scraper.py:336-340
  • Ghost cursor deliberately OFF — defensible. Synthetic mouse paths are themselves detectable; since we bail on Arkose we never need a cursor trace. commit 8e9fa97

🔵 What we should be doing (add these)

  • Default a wall-clock deadline_seconds (~30–40 min) so a span self-terminates near one session.high Today only max_reauths bounds the loop; there's no time budget. cli.py:645 · runner.py:121
  • Add a log-normal cooldown before each re-auth (NOT uniform).high Re-auths currently fire back-to-back; spacing them is the highest-value pacing fix — but sample the delay log-normally, not uniform. insert before runner.py:247
  • Type credentials & 2FA with press_sequentially, varied dwell + log-normal inter-key delay.med Removes the "pasted not typed" tell. Vary key-hold time too, not just gaps. session.py:386,411 · login_drive.py:1152
  • Add a brief human dwell between filling the password and submitting.med Submitting ~0ms after the last keystroke is a tell. session.py:411→420
  • Add a --max-windows flag (default ~6) so one login reliably covers a whole span.med Prevents wide spans from silently chaining re-auths. no flag today; runner default 12
  • Add a randomized inter-route delay in the multi-route watch loop.med N stale routes currently = N logins in quick succession. core/watchlist.py:198-218
  • Persist a last-login timestamp in the profile; enforce a minimum gap across separate process runs.low Each fresh process currently has no memory of the last login time. new
  • Upgrade ALL timing (incl. the existing scraper jitter) from uniform to log-normal / fat-tailed; vary session footprint run-to-run.med Defenders fingerprint uniform jitter specifically. scraper.py:336-340 + everywhere
  • KEEP one stable profile/fingerprint per account — do not rotate it.low For a logged-in account, consistency lowers the anomaly score; "freshening" identity raises it. (We already do this — just don't break it.)

🔴 What we should stop doing (remove these)

  • Stop defaulting interactive max_reauths to 4 — drop to 1–2.high A single manual search can fire up to 5 logins back-to-back in one span. runner.py:42 · cli.py:2960
  • Stop firing re-auths with zero cooldown (back-to-back logins).high Burst login velocity is the textbook account-freeze trigger. runner.py:247
  • Stop the cold-start retry that fires a 2nd login within seconds.med Two logins seconds apart on a slow form render. Add a backoff. session.py:299-315
  • Stop .fill()-pasting the member #, password, and 2FA code.med One atomic event, zero keystroke timing = "pasted, not typed." session.py:386,411 · login_drive.py:1152
  • Stop the fixed SETTLE_SECONDS = 3 between every login step.med Exactly-3.000s boundaries are a clockwork, human-implausible cadence. login_drive.py:85
  • Stop relying on random.uniform() as if it were camouflage.med Uniform jitter is an explicit detection target — replace with log-normal. scraper.py:336-340 + any new jitter
  • Don't add a ghost cursor / synthetic mouse movement.low Confirmed by research: detectable, low-value, can backfire. Keep it off. already off
